# 05 开发与发布路线

## 推荐技术路线

使用 Vite + React + TypeScript 建静态单页网站。它比直接写多个 HTML 文件更适合交互式技能树，又比完整服务器框架更适合 GitHub Pages。

## Phase 0：设计冻结（当前）

- 确认网站名称与公开身份。
- 确认视觉方向。
- 决定首页真实文案。
- 列出首批地图节点、技能和任务。

完成标志：本文件夹中的设计文档不再有结构性争议。

## Phase 1：可浏览骨架

- 初始化项目。
- 完成导航、首页和主题变量。
- 使用假数据搭出地图、技能树、任务页。
- 完成手机适配。

完成标志：所有页面可访问，暂无复杂交互也能读懂。

## Phase 2：真实内容与交互

- 接入 `src/data/` 的真实数据。
- 加入节点详情、筛选、缩放与当前位置。
- 加入任务状态和成就证据链接。
- 补充 About、GitHub 与联系方式。

完成标志：可以作为个人公开网站使用。

## Phase 3：质量检查

- 键盘可操作。
- 色彩对比度合格。
- 小屏幕无横向溢出（地图画布除外）。
- 刷新子页面不出现 404。
- 清理示例文字、密钥、私人信息和未发表内容。
- 检查标题、描述、favicon 和社交分享图。

## Phase 4：GitHub Pages 发布

### 仓库命名选择

- 想使用 `你的用户名.github.io`：仓库必须命名为 `你的用户名.github.io`。
- 想使用 `你的用户名.github.io/mysite/`：仓库可命名为 `mysite`，构建配置要设置正确的 base path。

本项目建议先用第二种，试运行稳定后再决定是否升级为个人主页仓库。

### 发布流程

1. 在 GitHub 新建公开仓库。
2. 在本地将 `mysite` 连接到仓库并推送。
3. 添加 GitHub Actions 构建与 Pages 发布流程。
4. 在仓库 Settings → Pages 中选择 GitHub Actions。
5. 等待首次发布完成，检查 Pages 地址。
6. 后续每次更新主分支都会自动发布。

GitHub Pages 可以从分支或 GitHub Actions 发布静态网站；个人域名可以之后再配置，不必作为第一版的阻塞项。

## 版本节奏

- `v0.1`：首页与静态页面骨架。
- `v0.2`：研究地图。
- `v0.3`：技能树与任务日志。
- `v0.4`：真实内容、响应式与无障碍。
- `v1.0`：公开发布并写第一篇 Dev Log。

## 每次更新检查表

- [ ] 是否泄露未发表数据或私人信息？
- [ ] 当前主线是否仍然只有一个？
- [ ] 新状态是否有证据或完成条件？
- [ ] 手机布局是否仍然可用？
- [ ] 所有外部链接是否有效？
- [ ] 本地构建是否成功？
