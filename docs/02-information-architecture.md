# 02 信息架构与页面

## 导航结构

```text
Home / Character
├── Research Map
├── Skill Tree
├── Quest Log
├── Achievements
├── Dev Log
└── About
```

桌面端使用左侧窄导航；移动端使用底部导航，并把次要入口折叠进菜单。

## 首页：Character Status

首页不是普通个人简介，而是“存档读取界面”。建议首屏顺序：

1. 身份：Radio Astronomy Graduate Student
2. 当前职业：H I Explorer；候选副职业：Pulsar Apprentice
3. 当前主线：确定第一个可执行的 H I 科学问题
4. 本阶段进度条：Foundation → Data → Question → Project → Paper
5. 三个立即行动：读一篇核心文献、操作一个 FITS cube、复现一张图
6. 最近解锁和最近日志

## 研究地图：Research Map

地图采用“星图 + 节点网络”，而不是地理地图。

- 大区域：射电基础、仪器观测、中性氢、脉冲星、瞬变、连续谱、21 cm 宇宙学。
- 节点状态：未发现、已发现、探索中、已掌握。
- 点击节点：打开侧边详情，显示简介、前置知识、相关技能、推荐任务和资料。
- 默认定位到当前区域，并提供“回到我的位置”。

## 技能树：Skill Tree

- 一级分支：基础工具、射电基础、数据处理、H I 科学、脉冲星、科研表达。
- 每个技能显示 0–5 级、前置技能、升级证据、下一级条件。
- 不能仅用颜色表示状态；同时使用图标、文字或边框。
- 提供“只看当前可升级技能”的筛选。

## 任务日志：Quest Log

任务分为：

- Main Quest：一个阶段只保留一个。
- Active Quest：当前最多 3 个，避免任务泛滥。
- Side Quest：补充能力，不阻塞主线。
- Completed：完成记录与成果链接。

每个任务卡片包含：目的、完成条件、预计投入、依赖、交付物、状态。

## 成就：Achievements

成就必须对应真实证据，例如：

- 第一次独立复现论文图表
- 第一次跑通完整数据流程
- 第一次公开组会报告
- 第一个可复现仓库
- 第一篇一作论文

避免“打开网页一次”这类无意义成就。

## Dev Log

用时间线记录网站与科研系统的迭代，而不是公开完整私人日记。每条包括日期、变化、原因和下一步。

## 关键用户路径

```text
首次访客
→ 首页理解身份与当前主线
→ 点击“查看我的位置”
→ 在研究地图了解方向
→ 查看技能树与完成证据
→ 前往 GitHub / 论文 / 联系方式
```

```text
作者每周维护
→ 更新任务状态
→ 更新一项技能证据
→ 新增一条 Dev Log
→ 本地预览
→ 提交 GitHub
→ GitHub Pages 自动发布
```
